# Current status

**PARTIAL (builds).** Aside is a desktop meeting copilot with a normal main window and a compact live overlay. It captures microphone and system audio separately, transcribes them, keeps a growing session context, and can answer spoken, typed, and screenshot questions. Aside is hidden from screenshots, recordings, and meeting screen-shares by default — that still needs a live owner check against Zoom and Cmd+Shift+3.

## Current product state

- **Hidden from screen sharing (2026-09-01, relaunch/always-on-top hardened 2026-09-02):** this is the main technical requirement. Aside stays on your display but is left out of screenshots, recordings, and meeting screen-shares (Zoom, Meet, Teams). The Dock and the Aside menu-bar menus are hidden too. Activity Monitor still lists Aside. Default is on. **Settings is the only on/off** — the checkbox now stages the change and asks "Turn on/off hiding?" first, since flipping it saves the choice and relaunches Aside so Dock and menu-bar policy apply from the first frame. The relaunch itself was flashing on screen and dying within about a second (a race in Tauri's own raw-binary restart); it now asks macOS to reopen the app bundle directly (`open -n`, the same thing Finder does), which does not have that race. While hiding is on, the main window also stays on top of every other window (and every macOS Space/fullscreen app) — it does not hide the window on your screen. The title-bar minus and ⌘⇧H hide Aside from your screen, and the next press brings the same windows back. The title-bar cross and ⌘Q always ask before quitting. A camera pointed at the screen still sees it.
- **Dark theme (2026-09-02):** Settings → Appearance toggles Light/Dark for the main window (same Acheron system, luminance inverted, canvas `#121212`). Defaults to the OS's own preference, then remembers your choice on this device. The live overlay is unaffected — it already always stays dark during a call.
- **Auto-answer removed (2026-08-31):** the old "guess a question is coming and answer it automatically" code path is gone from the Rust backend entirely, not just switched off — the function that used to do this, the timer that stopped it firing too often, and their tests were all deleted. The app only ever answers when you actually ask it to (Command+Enter, typed Chat, or Screenshot). This does not touch the separate "spot a likely question early and start the answer sooner" speed trick, which stays.
- **Settings:** Speech and AI model sit on one row. Cards show the control first, then at most two short lines of description. No copy under the Settings title. A saved API key hides the paste box and shows “Already saved” plus Change; the stored key is replaced only when you press Enter on a new one, and Cancel keeps the old key. Speed vs. cost is its own card below the models. Speech, AI model, and Speed vs. cost use themed dropdowns, not the macOS system menu. Edit on answer rules opens a full-window warning, then a full-window editor. Device pickers still live in the live overlay toolbar.
- **Copilots and documents:** reusable Copilots save call details, selected resumes, documents, instructions, and model choices in a fixed, non-scrolling centered editor. Automatic suggestions are off; Save transcript is the single call-record choice and enables the saved transcript, context notes, and AI summary together.
- **Conversation context:** Command+Enter, typed Chat, and Screenshot all use the same `window_memory` context path: stable default material plus the growing session summary. The obsolete recent-exchanges path was removed.
- **Live overlay:** separate microphone and system-audio controls start and stop their own transcription. Screenshot takes a fresh frame when clicked. The More menu stays inside the overlay, and the lower-right grip performs normal resizing. ⌘⇧H hides or shows the overlay on your screen.
- **Screenshot answers:** Screenshot uses the fixed `gpt-5.6-terra` preset. Without a spoken question, it is explicitly a factual screen review: it describes meaningful visible background content instead of falling back to an interview-response message. Coding and system-design answers explain themselves beside the relevant code or design element rather than in a detached explanation.
- **Libraries:** Copilots, Resume, and Documents are list-only. Resume and Documents now share Copilots' full-width header and clear primary action, so uploads no longer sit below a narrow side card.
- **Call history:** the history workspace is centered. Each completed call now has separate Conversation, Context notes, and AI Summary actions; conversation is shown as left/right chat bubbles, and Conversation and Context can be downloaded as text or PDF.
- **Visual system:** "Acheron" (2026-08-31) — sourced from the owner's own Google Stitch design system (project "macOS Theme Analyzer"). Flat monochrome black/white, 0px corners everywhere, hairline (1px black, ~10% opacity) borders, frosted glass panels, Space Grotesk for headline-tier text, JetBrains Mono for everything else (uppercase, wide tracking), underline-only form fields, and a chamfered-corner accent reserved for the app's one marquee CTA. Replaces the prior mineral-glass/violet system across the sidebar, libraries, forms, settings, dialogs, and history. The live overlay keeps the same monochrome system with luminance inverted for a dark call-time ground. Fonts are vendored locally under `public/fonts/` — no network fetch at runtime. See `docs/decisions.md` for the two judgment calls made (overlay stays dark; every text field goes underline-style) and the missing `references/Repo2-OpenCluely` gap found while checking the standing reference-repo rule.
- **Window size:** the main window is capped at 1600×1040 (`maxWidth`/`maxHeight` in `tauri.conf.json`) — still resizable/maximizable, but can no longer be dragged or maximized to fill an entire screen.
- **Distribution:** the project-root [Aside.app](/Users/devendra_r_n/Desktop/Projects/Aside/Aside.app) is the installed-style bundle. The bundle script removes disposable raw executables and refreshes the root bundle each run.
- **Answer cleanup backstop (2026-08-31):** after comparing Aside's own context-building (`window_memory/prompt.rs`, `STRICT_RULES`) against the app now vendored under `references/` (a different local-first meeting assistant, "Assistant"/`copilot-overlay`) — see `docs/decisions.md` for the full comparison — added one adopted improvement: a small, deterministic cleanup pass on the finished answer text (strips a leading "Certainly," "Sure," "Great question" opener and sentence-initial filler like "Furthermore,"; trims a dangling half-sentence if the stream ends mid-answer). This is a code-level backstop for what `STRICT_RULES` rule 34 already asks the model to do on its own — it doesn't change the prompt, only catches it when the model doesn't comply. Covers Command+Enter, typed Chat, and Screenshot together (`src/state/answers.ts`'s `answer-done` handler, the one place all three converge).
- **Sidebar's duplicate "Aside" removed, and the title bar's own buttons actually work now (2026-08-31):** the sidebar had a second, smaller "Aside" brand row directly below the title bar's own — a leftover from before the title bar existed. Deleted. Separately, the title bar's Minimize and Close buttons weren't working at all: the whole bar is a drag handle so the window can be moved by it, and without telling the browser engine otherwise, that "draggable" behavior swallows clicks on anything inside it, including the buttons — so Minimize did nothing and Close acted like some other unintended gesture instead of just closing. Fixed by explicitly excluding the button row from the drag behavior. The identical problem existed on every button in the live overlay's toolbar (Answer, Screenshot, mic/speaker, etc.) and was fixed there too before it could get reported separately.
- **One title bar, not two (2026-08-31):** the main window was showing the real macOS traffic-light title bar *and* the app's own custom bar underneath it (with its own logo, "Personal workspace" label, and its own minimize/close buttons) — a duplicate. The custom bar already fully replaces what a title bar does (it was built with `data-tauri-drag-region` and real minimize/close calls from day one), so `tauri.conf.json`'s main window now sets `"decorations": false` to turn off the native one and leave just the app's own. The live overlay window already had this set correctly.
- **App logo (2026-08-31):** replaced with the owner's "Aside Minimalist Logo Redesign" from the Acheron Google Stitch project — an arrow that also reads as an "A", next to an uppercase "ASIDE" wordmark. The macOS Dock/Finder icon (`src-tauri/icons/icon.png`/`icon.icns`) now uses the full arrow+wordmark lockup, masked into the usual rounded-square icon shape. The small in-app mark next to "Aside" in the sidebar and window title bar (`Icon.tsx`'s `mark`) was redrawn as a matching single-stroke vector of the same arrow, replacing the older "Spatial Glass" ribbon-A.
- **Call History, Copilots, and Documents/Resume tables rebuilt for automatic column alignment (2026-08-31):** in all three of the app's list tables, columns visibly drifted out of line row to row — a duration or date would sit at a different spot on one row than the row above or below it. First pass (superseded) tried fixed pixel widths for the drifting column; the owner asked for a real rewrite instead of a hardcoded-width patch. The actual cause: every row (including the header) was drawing its *own separate* column grid, so a row whose content differed in width from another row's — 4 small icon buttons vs. one "Join" button vs. a plain header word, or a long saved name vs. a short one — pulled a different width for the same column. Rebuilt all three tables on one new shared building block (`Table`/`TableRow`, `src/ui/Table.tsx`) where the header row and every data row are one single grid instead of many separate ones — so the browser measures each column's width from every row's content *together*, automatically, with no pixel number anywhere. Also fixed, found by stress-testing the new version with a long name: the Copilots and Documents "Name" column headers now sit above the actual saved names/files instead of above their small leading icon (done by making the header repeat an invisible copy of that same icon, not a guessed offset), and a very long copilot name now truncates with "…" instead of overflowing into the next column.
- **Question-type-aware answers, and Small/Medium/Long buttons (2026-08-31):** the answer rules (`STRICT_RULES`) now explicitly tell the AI to tell apart four things before answering — a real question, a plain statement with no question attached (answer conversationally, don't force a Q&A shape), and a coding or system-design request (real code in its own fenced block, a separate spoken-style explanation after it, never mixed together — matching what the overlay's answer card already renders as two visually separate sections). Adopted the reference app's idea of manual length buttons: the live overlay's toolbar now has three small "S / M / L" buttons next to Answer. Pressing one answers the current conversation immediately, same as Answer/⌘↩, but tells the AI to give a small (~15-40 word), medium (~40-90 word), or long (~90-180 word) answer for that one response — the plain Answer button and ⌘↩ keep deciding the length automatically, as before. This is a prompt instruction, not a hard code-enforced cap — the model is asked to stay in the band, not measured and truncated afterward.
