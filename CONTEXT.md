# Aside

## What this is

A personal AI copilot for meetings and interviews, for the owner and a couple of friends — not a commercial product. It listens in on a call, gives you private help (suggested answers, notes, context) that only you see, and runs on both macOS and Windows from one codebase.

The name: a theatrical "aside" is a private remark only the audience hears while the scene carries on. That's the shape of what this app does for you during a call.

## Architecture

- **Tauri** (Rust backend + web frontend), one process, one app, both platforms.
- **Hidden from screen sharing** (default on): Aside stays on your display but is left out of screenshots, recordings, and meeting screen-shares (Zoom, Meet, Teams). The Dock icon and the Aside menu-bar menus are hidden too. Activity Monitor still lists the process so you can quit it yourself. Settings is the only on/off; turning it on or off saves the choice and relaunches Aside so Dock and menu-bar policy apply from the first frame. It does not hide the window on your screen. The main window shows only red and yellow buttons (no green button, no full screen). Red quits at once without asking. Yellow hides every Aside window while screen-share hiding is on (Command+H brings them back; that key is claimed only while hidden) and minimizes to the Dock like any app when it is off. The app menu's Quit still asks first. A camera pointed at the screen still sees it.
- `src-tauri/` — Rust. Split by job: `domain/` (sessions), `audio/` (mic + speaker capture, speaking-lights, and laptop-speaker echo cancel on Me only), `stt/` (speech-to-text engines), `pipeline.rs` (live capture → transcription), `conversation/` (both ears, Prepare-only while auto-answer is off), `window_memory/` (Command+Enter conversation windows + session memory), `llm/` (one cloud answer request), `storage/` (SQLite), `commands/` (what the frontend calls: audio, session, stt, llm, documents, capture, rag).
- `src/` — React + TypeScript + Vite, rebuilt 2026-09-25 (branch `redesign-dock`). One bundle, two windows: `main.tsx` mounts the workspace (`home/`) in the normal window and the live call (`live/`) in the second, always-on-top `overlay` window. Folders: `bridge/` (the only place that talks to Rust: typed commands in `api.ts`, event names, shared types), `core/` (pure helpers with tests: tiny store, question detection, answer cleanup/parsing, exports, formatting), `kit/` (buttons, dialog, form fields, toasts, icons), `theme/` (colour tokens for light and dark, base styles), `live/` (the docked call window: a pure state machine `machine.ts`, a controller, and the screens), `home/` (Copilots, Resumes, Documents, History, Settings, plus the pre-call readiness rules). Styling is plain CSS with design tokens; the type is the Mac's own system font.
- **Live window:** one plain question-and-answer panel built from the main window's pieces (near-black ground, box-free sections divided by hairlines, boxed controls), see-through by the Background setting (neutral greys, no accent colour, no blur). The question is the title; under a hairline, the answer is the only part that scrolls. A single top bar holds a status dot with the call clock, You and Them as icon buttons that brighten while sound comes in, answer history ‹ 2/5 › (also ⌘< / ⌘>), window options and End (four-second cancel). Below it, the question and its answer fill the window: the answer is plain text with any list or code the AI wrote, with no title, badge or option buttons; only a failed answer adds a Try again line. A single bottom bar holds a follow-up box (Enter sends), Screenshot answer and Answer (⌘↩). Window options: Background (40–100%, how solid the panel is; text stays solid with a halo below 75%), Text size (Small, Medium, Large, Extra large, scaling the question, answer and code), Pause listening, Reset window, Open Aside. Problem alerts (mic, system audio, offline, paused) appear under the top bar only when needed. No transcript view, layouts or length buttons. All edges and corners have resize targets; macOS uses a short-lived native mouse-drag tracker because Tauri does not support resize dragging there. `src-tauri/src/window_fit.rs` keeps windows on the usable screen. Ending a call closes the live window and shows a "Call ended" sheet in the main window.
- **Workspace design:** one near-black look in the Geist font; no search box at the top (the strip there only drags the window and shows Return to call); the main window is solid (nothing behind it shows through), the live window's see-through amount is the person's Background setting (no blur); layered surfaces with soft shadows, and a single deep emerald accent used only for the main action, the current place and things that are on. Content sits in one 720px column on every page. Copilot has the title, role and a ⋯ menu at the top, then box-free sections divided by hairlines: Job description (Edit and Add URL at the right; the job-post link field opens only after Add URL), Resume and Supporting files side by side, and Guidance. AI model, Save transcript and Start session float at the bottom right with the saved state beside them, with no bar behind them; everything fits the 1180×860 window without scrolling. Job description and Guidance show four whole lines with a Show more link that opens the full text in place. Settings uses the same box-free sections (small icon beside the title, content under it, hairlines between sections and rows), fits the window without scrolling, shows the four shortcuts as a 2×2 grid and Strict rules as four lines with Show more. Copilot, Settings, Library and History share one content column with identical edges, the same 24px page title with no icon, and the same box-free sections held together by one rounded border per page (the page title sits above it); only things you type into, drop onto or press keep a shape. Library is one bordered group whose header holds the filter, search and list/grid toggle; History has one section per day inside one border. File and call details show as plain icon-and-text facts, not outlined chips. Library and History show facts as small chips. The main window is fixed at 1180×860 (with the existing screen-fit safety); only the live window permits user resizing. Shared color and motion tokens carry through the live window.
- **App shortcuts:** only Command+Enter (Answer), Command+Shift+Enter (Screenshot answer), Command+< (previous answer), Command+> (next answer), registered as Command+Shift+Comma/Period. Rust registers them globally. Settings and the live menu share the same four labels. Search opens from the sidebar button. Window menu actions are clickable without extra app shortcuts; standard text editing keys remain native.
- **Dev preview:** `npm run dev`, then open `/?demo=live` (a pretend call; add `&scn=silent|offline|mic` for recovery cards, `&mode=capsule`) or `/?demo#/copilots` (workspace with made-up data). These exist only in development builds.
- Local SQLite (`aside.sqlite3` in the app data directory) is the notebook. Final transcripts are written as they land; a live owner click-through of quit-and-reopen is still owed.
- **Command+Enter** freezes everything spoken since the last press (finals plus the latest interim words); when nothing new has been spoken, it reuses the last window from this session. Every click sends one cloud request: strict rules + cached default documents + compressed memory + that raw window. The screen shows the answer as soon as the first words arrive. Hidden memory updates after. Auto-answer stays off. **Command+Shift+Enter** requests a screenshot answer through the same path as the live camera button. A screenshot is sent to the configured LLM provider's vision endpoint when triggered — same trust boundary as every other answer request in this app, no new provider or new data path.
- No protobuf, no cross-language wire format — it's one process, so plain JSON over Tauri's built-in command/event bridge is the whole data layer.
