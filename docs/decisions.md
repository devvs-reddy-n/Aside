# Decisions

This is the compact record of decisions that still affect the product. Superseded implementation narration was removed on 2026-08-30.

## Product shape

- Aside is a small personal desktop meeting copilot, not a hosted service. It is built with Tauri/Rust and React/TypeScript.
- The product uses a main application window and a separate live overlay created for an active session. The overlay remains compact, dark, resizable, and always-on-top.
- The project compares new features with the vendored Natively and OpenCluely reference repositories, adapting ideas rather than their code.

## Audio and transcription

- Microphone and system audio are independent routes and remain distinguishable in the UI and stored transcript.
- Finals, not transient partial text, form the durable conversation record. Same-speaker messages can be joined across a natural think-pause.
- Speechmatics uses its realtime route and treats end-of-utterance as the sentence boundary. Recoverable device sample-rate changes rebuild the system-audio path.
- Laptop-speaker echo is handled only for that physical situation, using AEC plus conservative duplicate filtering; headphones remain the preferred route.

## Context and answers

- Command+Enter sends cached stable context, session material, a compressed growing memory, and the current spoken window in one answer request.
- `window_memory` is the only conversation-memory mechanism. Typed Chat and Screenshot use it too; the older recent-exchanges path and its settings were removed.
- Document text is session material, not a separate product mode. Parsing supports PDF, DOCX, and text.
- Screenshot uses a fixed `gpt-5.6-terra` preset so it does not depend on a session model that may lack vision support.
- A Screenshot with no spoken question is a screen-review request: it describes relevant visible content rather than inventing an interview prompt or reporting only Aside's controls. Rendered text remains untrusted content and is never executed as an instruction.
- Coding and system-design screenshot responses explain meaningful parts inline, rather than separating code from its explanation.

## User experience

- The main application uses a light workspace language: white and blue-grey planes, soft raised/recessed depth, and a violet primary action. Aside keeps its own name and real content rather than using the supplied template's demo branding or fake data. The live overlay remains dark for call-time contrast.
- The 2026-08-30 visual refresh standardizes every main-window surface around one mineral-glass recipe: a cool canvas, translucent planes, crisp edges, 16px surface corners, 12px controls, and a single violet action color. The overlay keeps the same hierarchy with dark values so it remains readable during a call.
- **2026-08-31 "Acheron" redesign** replaces the mineral-glass system above, sourced from a Google Stitch design system the owner built (project "macOS Theme Analyzer", design system "Acheron Interface"): flat monochrome black/white, 0px corners everywhere, hairline (1px black, ~10% opacity) borders, frosted glass panels, Space Grotesk for headline-tier text only, JetBrains Mono for everything else (labels/body/buttons, uppercase, wide tracking), and an optional 45° chamfered-corner accent reserved for the app's one or two marquee CTAs (Start Call, the "aw-cta" primary action). Fonts are vendored locally under `public/fonts/` (variable woff2, JetBrains Mono + Space Grotesk) — the prior "no font files, no network font fetch" constraint is now "no network fetch at runtime" only; the app never depends on internet access to render its own type.
- The live overlay **stays dark** under Acheron rather than switching to light — the Stitch project only produced one (light) design-system variant, and low glare during an actual call is a real, existing UX property (not something Stitch was asked to reconsider). Its palette is the same monochrome system with luminance inverted (near-black ground, white hairlines), not a separate look.
- Text inputs, selects, and textareas across the whole app (shared `u-input`/`u-select`/`u-textarea`, the Create/Connect flow's own `sc-input`/`sc-textarea`/`sc-dropdown__trigger`, and the Copilot editor's fields) switch from the old boxed/filled field to Acheron's underline-only style — bottom border only, label above, no fill. This is the most visually noticeable ripple of the redesign since nearly every form in the app uses one of these three field families.
- `references/Repo2-OpenCluely` does not exist in this repo (checked 2026-08-31) — only the Natively-equivalent app is vendored under `references/`. Flagged rather than silently skipped; the standing "check both references" rule in `CLAUDE.md` currently only has one repo to check against.
- **2026-08-31:** the main window (`src-tauri/tauri.conf.json`) got an explicit `maxWidth: 1600, maxHeight: 1040` — owner request. It stays resizable/maximizable (still feels "full-sized" on a small laptop screen) but can no longer be dragged or maximized edge-to-edge on a full monitor.
- Copilots, Resume, and Documents are list-first libraries. Their Grid/List controls were removed; Resume and Documents use the same full-width page header and primary action as Copilots.
- Copilot setup uses a compact, fixed centered dialog, not a side drawer or a scrolling form. Automatic suggestions are removed from the setup; one Save transcript checkbox controls the durable transcript, context notes, and AI summary record.
- Call history keeps conversation, rolling context notes, and a whole-call AI summary as separate views. The summary is on-demand, uses only the final two-sided transcript, and returns a factual paragraph plus concise highlights; it does not alter stored context or future suggestions.
- Overlay controls must perform a visible action: audio controls start/stop their matching route, Screenshot captures a fresh frame on click, menus stay within the window, and resizing uses a native grip.
- Settings expose real behavior in plain language. Device selection belongs to the Speech engine area; obsolete or duplicated options are removed rather than hidden.

## Reliability and delivery

- SQLite is the local source of truth for durable product data.
- Conversation and Context exports are generated locally in the UI as plain text or a compact Helvetica PDF, so exporting a record does not require new filesystem permissions or send call data anywhere.
- Build verification includes frontend and Rust builds, focused tests for changed logic, and a rebuilt root `Aside.app`.
- The app bundle is ad-hoc signed unless an explicit signing identity is supplied; rebuilds can therefore require macOS permissions again.

## Auto-answer removal and Settings rebuild (2026-08-31)

- The "automatically answer when speech looks like a question" feature is deleted from the Rust backend, not just switched off: the gating function, its cooldown timer, and their tests are gone from `llm/mod.rs` and `llm/trigger.rs`. The separate "detect a likely question early and start generating sooner" latency trick (`conversation/hypothesis.rs`) is unrelated and stays; it never auto-answers on its own, it only prepares.
- Settings is trimmed to exactly three cards: speech engine, AI model (which now also carries OpenAI's service-tier choice, since that is a request-level setting for whichever model is picked, not a separate concern), and the strict answer rules. The old fourth "Advanced" card was removed.
- Microphone/system-audio device selection moved out of Settings entirely into a small quick-switch next to the mic/speaker icons in the live overlay's own toolbar, since mid-call is when you actually want to change a device, not while browsing a settings screen. It reuses the exact same device list and `chooseDevice` logic Settings used to call — no new backend command.
- The device-picker dropdown is left-aligned to its trigger rather than centered, because the mic icon sits near the very left edge of the (narrow, 720px) overlay window; a centered popover was clipped off-screen there in browser-preview testing and had to be fixed before this was called done.

## Reference-repo comparison: context sent to the LLM, and the default rules (2026-08-31)

`references/` was replaced at some point with a different vendored app (package name `copilot-overlay`, "Assistant" — a local-first, multi-window, Electron/Ollama meeting assistant with no cloud dependency) — the `Repo1-Natively`/`Repo2-OpenCluely` layout `CLAUDE.md` describes no longer matches what's actually vendored there; only this one project exists now. Compared its `ChatService.ts`/`modes.ts`/`humanize.ts`/`answerLength.ts` against Aside's own `window_memory/prompt.rs` (context assembly) and `STRICT_RULES` (the default rules).

**Where they differ on purpose, not adopted:**
- The reference uses short (~100-150 word), swappable per-"Mode" personas (Meetings, Interview practice, Sales, Coding, ...) instead of one fixed rule set. Aside's single 54-rule `STRICT_RULES` block is deliberately exhaustive for one specific, harder problem — live, noisy, single-speaker-disambiguated interview transcription — that a general multi-mode assistant doesn't have to solve as rigorously. A "Modes" system would be a scope addition, not a same-problem improvement `CLAUDE.md`'s comparison rule calls for, so it wasn't built.
- The reference hard-truncates a finished answer to fit a length band (`enforceLength`). Aside's own rule 27 explicitly rejects that: "Never pad an answer merely to satisfy a requested length... a genuinely complete answer that lands under it is still correct" — hard truncation would cut real content mid-thought. Not adopted; Aside's length control stays prompt-level guidance only.
- The reference's newest-first, per-turn token-budget history walk vs. Aside's staged-fallback truncation (drop other docs → drop oldest window summaries → shrink resume/JD) are both reasonable "never cut the newest thing" strategies for their own different context shapes (open-ended chat history vs. Aside's fixed four-section prompt). Neither is a clear improvement over the other; left as-is.

**Adopted — a real gap, not a difference of taste:** the reference runs a small, deterministic, regex-based cleanup pass on the *finished* answer text (`humanize.ts`'s `tightenAnswer`, `answerLength.ts`'s `trimDanglingTail`) as a code-level backstop behind its prompt instructions, then patches the displayed/stored text if cleanup changed anything. Aside's `STRICT_RULES` rule 34 already *asks* the model not to open with "Absolutely," "Certainly," or "Great question" and to end on a real sentence — but nothing enforced either one; a model that ignored the instruction just... ignored it, with no rewrite of the actual repeated backend prompt build. Implemented `src/state/answerCleanup.ts` (adapted, not copied — different language, different answer shape given Aside's own code-fence/Key-Steps parsing in `answerParse.ts`) and wired it into `useAnswerStream`'s `answer-done` handler in `src/state/answers.ts`: strips a leading AI-tell opener and sentence-initial filler ("Furthermore," "It's worth noting that," ...), and trims a dangling half-sentence if the stream ended mid-answer (bailing out if the trailing fragment contains a newline or backtick, so a cut-off code block or bullet list is never mangled). Pure, idempotent, frontend-only — no Rust/event-contract change needed, since the frontend already holds the full accumulated answer text the moment `answer-done` fires; both `WindowAnswerSink` and the plain ask/screenshot path converge on the same `answer-*` events, so this one fix point covers Command+Enter, typed Chat, and Screenshot together. Skipped entirely for a canned fallback message (Aside's own fixed wording, not model output).

## Duplicate sidebar brand removed; drag-region was swallowing button clicks (2026-08-31)

- `Sidebar.tsx` had its own `.aw-sidebar__brand` row (icon + "Aside") directly below the title bar's own, from before `WindowChrome.tsx` existed as the app's real title bar. Deleted, along with its now-unused CSS (`.aw-sidebar__brand`, `.aw-sidebar__brand svg`).
- Real bug, not cosmetic: the title bar's Minimize and Close buttons did not work — Minimize did nothing, Close behaved like some other unintended window gesture instead of calling its own `close()` handler. Root cause: `.aw-chrome` is a `data-tauri-drag-region` (needed so the bar itself drags the window), and WebKit's `app-region: drag` is inherited by descendants unless a descendant explicitly opts out with `app-region: no-drag` — nothing did, so the OS was treating a mousedown on the buttons as the start of a window-drag instead of delivering the click. Fixed with `-webkit-app-region: no-drag` on `.aw-chrome__actions`.
- The identical bug existed on every control in the live overlay's toolbar (`.ov-toolbar` — Answer, Screenshot, the mic/speaker toggles, the device pickers, the opacity slider, Collapse, More, the timer/End button) for the same reason, and was fixed the same way before it could surface as its own bug report. This had gone unnoticed because the browser-only dev preview (used for most of this project's visual verification) never exercises real Tauri drag-region behavior — it's a no-op attribute outside a real Tauri window, so this class of bug is invisible to that verification path and can only really be caught by clicking the actual buttons in the installed app.

## Native title bar removed on the main window (2026-08-31)

- The main window was rendering both the real macOS traffic-light title bar and the app's own in-webview title bar (`WindowChrome.tsx`) stacked on top of each other. `WindowChrome.tsx` was already a complete replacement (drag region, real minimize/close calls) — the only thing missing was `"decorations": false` on the main window entry in `tauri.conf.json`; the overlay window already had it. No CSS changes were needed since `aw-chrome` was already a full-width bar with no space reserved for native traffic lights.
- Losing this also drops the native green "zoom"/fullscreen button, with no custom replacement — accepted as consistent with the existing 1600×1040 max-size cap decision (a maximize control wouldn't have done much anyway).

This replaces the older "Spatial Glass" ribbon-A on both surfaces.

Both times, stripping xattrs and verifying immediately by hand (no `sleep`) succeeded on the very next attempt — the underlying signature was never actually broken, just the verification timing. ## Call History / Copilots table column alignment (2026-08-31)

- Owner reported, with an annotated screenshot, that Call History's and Copilots' table columns didn't line up — most visibly on the newest/first row in each table.
- Root cause (both tables): `.ss-table`/`.cp-table` is `flex-direction: column` with each row (header included) being its own independent `display: grid`. `grid-template-columns` used `fr` units for the data columns and `auto` for the trailing action column. `fr` tracks split whatever space is left *after* the `auto` track is sized to that row's own content — so a row whose trailing content differs in width from other rows (Sessions: the active row's single "Join" text button vs. an ended row's 4 fixed 30px icon buttons vs. the header's plain "Action" label; Copilots: a data row's "Start →" button vs. the header's empty spacer) ends up with different actual pixel widths for the *other* columns too, even though the CSS rule text is byte-identical across every row. Fixed by giving the trailing column a fixed pixel width on both tables (152px for Sessions, sized for the 4-icon case: `4*30 + 3*8 = 144px`; 96px for Copilots, sized for "Start →") instead of `auto` — every row's grid then computes identical column widths.
- Second, separate bug on Copilots only: the Name column's real content (`.cp-table__name`) leads with a 32px avatar swatch + 10px gap before the name text, but the plain "Name" header label had no matching offset, so the label and the values it labels never shared a left edge. Fixed with a dedicated `.cp-table__name-head { padding-left: 42px }` (32+10, the avatar+gap it's compensating for) on that one header cell.
- Considered but rejected: rebuilding both tables as a single shared CSS Grid (or subgrid) so no row can ever size independently again — the more "correct" long-term fix, but a much larger change (real `<table>` semantics or subgrid browser-support tradeoffs) for a bug a fixed trailing-column width already fully resolves given today's fixed set of columns.
- Verified visually without a live Tauri backend (the browser-only dev preview's Call History/Copilots tables are always empty — no real session/copilot data reachable there): reproduced the exact JSX markup and real `sessions.css`/`copilots.css` in a standalone HTML file with fixture rows matching the owner's screenshot (an active row + two ended rows with icon actions; one copilot row with an avatar), rasterized via macOS `qlmanage` (the Browser pane's `file://` tabs render as inert static snapshots, so screenshot/JS tools don't work on them — same limitation hit earlier this session tracing the app-icon SVG). Confirmed all four Sessions columns and all four Copilots columns line up across every row after the fix.

## Table alignment fix, take two: rebuilt instead of patched (2026-08-31)

- The fixed-pixel-width patch above (152px/96px trailing columns) visibly worked but was a workaround, not a fix — it hardcoded a guess at the widest possible trailing-column content instead of letting layout handle it. The owner explicitly rejected this after seeing it was "still same" on a third table (Documents) they hadn't shown before, and asked for a from-scratch rewrite with no hardcoded pixel widths, automatic placement.
- Real root cause (confirmed by inventorying all three tables, `Explore` agent): `.xx-table` was `flex-direction: column`, and each `.xx-table__row` — header included — was its *own independent* `display: grid`. Two independent grids with textually-identical `grid-template-columns` still compute different actual pixel widths per row whenever their `fr`/`auto` tracks are fed different content, which they always are here (a header's plain label vs. a data row's icon buttons/avatar/badge).
- New shared primitive: `Table`/`TableRow` (`src/ui/Table.tsx`, exported from `src/ui/index.ts`). `Table` renders one `.u-table` (`display: grid`); `TableRow` renders `display: contents` (`ui.css`) so a row contributes no box of its own — its cells become direct grid items of the *single* parent grid. One grid measures every column from every row's cells together, automatically — this is what "automatic placement" actually means in CSS Grid, and it needs no column-width number anywhere. Each page still owns its own `grid-template-columns` via its own class (`.ss-table`/`.cp-table`/`.dc-table`), same as before — only the "one independent grid per row" structure is gone. All three tables (Sessions, Copilots, Documents) were rewired onto this in the same pass, since they shared the identical bug and there is no other table pattern in the codebase (confirmed by grep) — a fourth would only reintroduce the bug a fifth time if left as copy-pasted markup instead of one shared piece.
- `display: contents` removes an element from the *box* tree but not the *DOM* tree, so `:first-child`/`:last-child`/`:nth-child`/`+`-adjacent-sibling selectors on a row's cells all kept working unchanged — every existing per-row border/padding/responsive-collapse rule in `sessions.css`/`copilots.css`/`documents.css` was retargeted from the (now-boxless) row to `.xx-table__row > *` (its cells) with no loss of behavior, including Sessions' narrow-screen column-collapse and Documents' horizontal-scroll-instead-of-collapse strategy.
- Two real bugs surfaced only once tested with longer fixture content than the owner's screenshots showed (a header that itself needs a tall element, a longer saved name) — both fixed in the same pass since they're the direct product of "one shared grid" being new:
  - The Copilots/Documents "Name" column header used to either sit flush left (looked wrong) or get a guessed `padding-left` (still a hardcoded number). Fixed by having the header repeat the *exact same* leading-icon element (`cp-card__initial cp-card__initial--sm`, or the real `Icon name="document"`) made invisible (`u-invisible-spacer`, `ui.css` — `visibility: hidden`), so the header's reserved space is never a guess and stays correct automatically if the real icon's size ever changes.
  - Once a row's header cell got visually taller (the invisible avatar spacer), the shared grid's row height grew to match, but shorter sibling cells' backgrounds didn't grow with it, since `.u-table` used `align-items: center` (each cell only as tall as its own content) — producing a visibly broken/jagged header background. Fixed by using `align-items: stretch` (the grid default) plus a shared `.u-table__row > * { display: flex; align-items: center }` base so every cell fills its row's actual height and centers its own content within that — page-specific cells that need different internal layout (e.g. Sessions' stacked title+meta, `.ss-cell-title`) explicitly override `align-items` back to `flex-start`, since the cascade lets a later, page-specific rule win on the tied specificity.
  - Separately (not new, but only visible once tested with a long name): Copilots' name+subtitle wrapper `<span>` had no `min-width: 0`, so flexbox's own default (`min-width: auto` on a flex item) let a long name silently defeat its own `text-overflow: ellipsis` by forcing the wrapper — and the column — wide enough to fit the whole string. Given `min-width: 0` an explicit class (`cp-table__name-copy`) rather than leave it as an anonymous, easy-to-regress wrapper.
- Verified the same way as the first pass (no live Tauri backend reachable from the browser-only dev preview for any of these three tables): a standalone HTML file reproducing the real component output and the real CSS files, this time deliberately including a long copilot name and a short one side by side to stress-test truncation and header-height interaction, not just the exact rows from the owner's screenshots. Rasterized via `qlmanage` (file:// tabs are inert in the Browser pane sandbox). Two bugs were caught and fixed this way before shipping — see the two bullets above — which is the reason to test with harder fixtures than what was reported, not just reproduce the exact failing case.

## Question-type-aware answers and manual answer-length buttons (2026-08-31)

- Owner request: the AI should tell apart a real interview question, a plain statement with no question in it (should get a short conversational reply, not a forced answer), and a coding/system-design request (should get real code in its own block plus a separate explanation) — and the reference app's Small/Medium/Long transcript buttons should become real in Aside.
- `STRICT_RULES` (`window_memory/prompt.rs`) gained a new numbered section (rules 55-58) plus two worked examples, rather than rewriting the existing AUTO-length table (rule 25) or the SHORT/MEDIUM/LONG in-conversation override (rule 26) — those already existed and worked; this just makes the classification step explicit and adds the coding/architecture answer shape, which had no rule before.
- For code/architecture answers, the rule points at the frontend's existing split: `answerParse.ts` already pulls a fenced code block into its own bordered, monospace `CodeCard` separate from the prose `AnswerBody` — so the fix needed was telling the model to actually produce that shape (fence + separate prose), not building new UI.
- The manual length override is a genuinely new mechanism, modeled on the reference app's `forceLength`/`forcedLengthDirective`, but scoped down: Aside implements 3 bands (Small/Medium/Long) matching the owner's own wording, not the reference's 4 (it also has "1-liner"). The directive text reuses rule 25's own word-count bands verbatim so a manual press and the model's own AUTO judgment never disagree about what "small" means.
- Deliberately **not** ported: the reference's code-level enforcement (`enforceLength`'s hard sentence-boundary trim, the streaming `[[LEN:...]]` tag/filter). This is a prompt instruction only — the model is asked to stay in the band, not measured and truncated afterward. Scoped down to match what "make the buttons functional" actually required; a hard cap is a reasonable follow-up if the model turns out to ignore the directive in practice (owner check #14).
- New Rust type `LengthOverride` (`window_memory::LengthOverride`, `small`/`medium`/`long`) is threaded through as an `Option`, appended only to the `user` half of the prompt, never `system` — `system` must stay byte-identical across requests for the OpenAI prompt-cache floor to matter (same reasoning the reference app's own comment gives for the identical choice), and `user` already changes every request anyway.
- Threaded only through the Command+Enter/Answer-button path (`trigger_window_answer` → `respond_to_window` → `window_answer_with_claim`), not the typed-Chat/Bench `trigger_answer` path — that's the one the owner actually asked about ("if I press long then it should do the job as answer or cmd+enter"), and keeping Chat's signature untouched avoids widening the change for no requested benefit.
- To avoid touching ~25 existing test call sites of `build_prompt`/`build_request`, both kept their old signature as a thin `None`-passing wrapper around a new `_with_length` variant that carries the real parameter — an additive change, not a rename.
- Placement: three small "S"/"M"/"L" buttons live in the always-visible overlay toolbar, directly beside Answer (not in the collapsible body, where the reference app's own `LengthBar` sits) — the owner's flow presses one *instead of* Answer, so it needs to be reachable before any answer body exists yet.

## Screen-share hiding (2026-09-01)

- Owner request: the main technical requirement for Aside is the same "hidden from screen sharing" behavior the vendored reference app (`references/`, Electron `setContentProtection`) ships. Aside stays on the owner's display; screenshots, recordings, and meeting screen-shares (Zoom, Meet, Teams) do not show it. A camera pointed at the screen still would — same honest limit the reference documents.
- Earlier code comments treated this as forbidden. The owner explicitly reversed that and asked to implement it anyway. The OS call is Tauri's `set_content_protected(true)` (`NSWindowSharingTypeNone` on macOS, `WDA_EXCLUDEFROMCAPTURE` on Windows). Default is **on**, matching the reference (`screenShareInvisible: true` at first launch).
- One saved flag (`settings.screen_share_invisible`), applied to every live window at creation and on toggle. Settings is the only on/off. Collapse (⌘H) still only hides the answer body. ⌘⇧H hides or shows Aside on the owner's own display.
- When hiding is off, a Screenshot / ⌘K grab briefly hides Aside's own windows first (150ms, same delay the reference measured) so the helper never photographs itself. When hiding is on, the OS already leaves those windows out of the frame, so we skip the flash.
- Overlay `skip_taskbar(true)` is set because it is a floating tool, not a second document window. That flag is a no-op on macOS in the window library we use; it matters on Windows.
- **Dock and menu bar (2026-09-01, owner follow-up):** hiding must also remove the Dock icon and the Aside menu-bar menus. macOS `ActivationPolicy::Accessory` plus `LSUIElement` in `Info.plist` does both from the first frame. Activity Monitor must still list the process as Aside — the owner asked for that explicitly (so they can quit it). No process-name disguise, no extra helper binary. Turning hiding off restores a normal Dock icon and menu bar (`ActivationPolicy::Regular`).
- **Settings hide must not hide the window (2026-09-01):** `set_dock_visibility(false)` was taking the main window off the screen because it calls `TransformProcessType` to UIElement. Removed. Accessory policy is enough for Dock/menu bar. ⌘⇧H is no longer the stealth toggle — Settings is the only on/off. ⌘⇧H now hides or shows Aside on the owner's own display (same windows come back on the second press); capture keeps running.
- **Stealth toggle relaunches (2026-09-01, owner follow-up):** changing Hide from screen sharing on or off saves the flag and relaunches Aside. Dock / menu-bar policy is applied at launch from the saved flag; changing it mid-process was leaving the window, Dock, or menus in the wrong state.
- **Title-bar minus hides, cross quits (2026-09-01, owner follow-up):** the minus is the same action as ⌘⇧H (hide from your screen, not minimize to the Dock). The cross is the same action as ⌘Q. Quit always asks first (title-bar cross, ⌘Q, and Aside > Quit). The OS predefined Quit item is replaced so macOS cannot terminate without that dialog. A stealth relaunch does not ask.

## Settings layout (2026-09-01)

- Speech and AI model stay on one row. Speed vs. cost (Normal / Flex / Priority) moves to its own card below — it is a request lane, not part of picking the model.
- A saved API key does not show a paste box. The row reads “Already saved” with a Change button. Change shows a warning; the stored key is replaced only when Enter is pressed with a new value. Cancel, Escape, or Close keeps the old key. This matches the reference app’s “key already saved, don’t re-show it” idea, but does not delete the key on entering edit (the reference leaves a blank field that reuses the saved key; Aside hides the field until Change).
- Settings has no copy under the title. Every card puts the control first and at most two short description lines after it.
- Edit on answer rules opens a full-window warning, then a full-window editor (same chrome and size as Settings). Closing without Save leaves the stored rules unchanged.
- Settings dropdowns (speech, AI model, speed vs. cost) are custom L3 menus, not native macOS `<select>` popups, so the list matches Aside's type, color, and sharp corners. Native `<option>` menus cannot be themed on macOS.

## Stealth: reliable relaunch, always-on-top, and a confirm prompt (2026-09-02)

- Owner report: toggling "Hide from screen sharing" in Settings relaunches Aside (by design, see above), but the new process would flash on screen and die within about a second, leaving nothing running and forcing a manual reopen from Finder.
- Root cause: the relaunch used Tauri's own `AppHandle::request_restart()`, which re-executes the binary directly (`Command::new(<path-to-binary-inside-the-.app>).spawn()`) instead of asking macOS to open the app bundle the normal way. That raced with the still-shutting-down old process. Fixed by relaunching through `open -n <bundle path>` instead — the same thing Finder does on a double-click — with `AppHandle::request_restart()` kept only as the fallback for a dev (`cargo run`) binary that isn't inside a real `.app` bundle. See `stealth.rs`'s `relaunch`/`relaunch_via_open`/`bundle_path_from_binary`.
- Owner request: while hiding is on, Aside should never disappear behind another app just because that app was clicked into or made fullscreen — ⌘⇧H should be the *only* thing that hides it. `apply_to_window` now also sets `always_on_top` and `visible_on_all_workspaces` to the hiding flag for the main window (not the overlay, which is already unconditionally always-on-top for its own, unrelated reason: floating over a live call regardless of this setting).
- Owner request: flipping the Settings checkbox should ask first, since it closes and reopens Aside. Added a confirm dialog in `StealthCard.tsx` (same shape as the existing Quit confirmation) — the checkbox only stages the change; "Turn on/off and reopen" is what actually calls `setEnabled`, Cancel reverts the checkbox with no backend call at all.
- Not owner-verified live: this environment cannot open the installed macOS app, so the actual relaunch and always-on-top-across-Spaces behavior are code-reviewed and unit-tested (`bundle_path_from_binary`'s path math) rather than clicked through for real. See `docs/evidence.md`.

## Dialogs trapped inside a blurred ancestor (2026-09-02)

- Owner report (with a screenshot from the installed app): the Quit confirmation appeared as a cropped strip of buttons stuck at the very top of the screen, overlapping another app's window, with no dimmed backdrop — not the centered "Quit Aside?" modal it should be.
- Root cause: a CSS rule most people never hit on purpose. `position: fixed` is normally relative to the whole window viewport — *unless* an ancestor element sets `backdrop-filter` (or `transform`/`filter`/`will-change`), in which case that ancestor becomes the fixed element's containing block instead. `WindowChrome.tsx` renders the Quit dialog (`{quit.dialog}`) as a child of `.aw-chrome` — the 36–44px title-bar strip, which has `backdrop-filter: var(--l1-blur)` for its own frosted-glass look (`window.css`). The dialog's "fixed, cover the window" backdrop got trapped inside that 44px-tall box instead of the real window, so only whatever of it fit inside that sliver was visible — the buttons — with no room for the title, body, or a visible dimmed backdrop.
- This isn't unique to the title bar: `Dialog` is used from inside `.aw-sheet` (Settings) and other frosted-glass surfaces too, all of which set `backdrop-filter`. The Settings ones happened to look fine only because `.aw-sheet` is nearly full-window-sized, so the trapped containing block was large enough to hide the bug — not because they were actually escaping it.
- Fixed at the source rather than patching this one call site: `ui/Dialog.tsx` now renders through `createPortal` to `.aw-root` (falling back to `document.body`) — the same escape-the-ancestor pattern `Select.tsx` already uses for its dropdown menu, for the same underlying reason. Every current and future `Dialog` (Quit, the stealth-toggle confirm, answer-rules warning, session delete/context/conversation/summary dialogs, the Create Copilot dialog) is now immune to whichever glassy ancestor it happens to be opened from.
- Verified in browser preview: clicking the title bar's Quit button now shows a properly centered "Quit Aside?" modal with its title, body text, and blurred/dimmed backdrop covering the whole window — not the cropped top-strip from the owner's screenshot.

The reference screenshot ("Aside Next"/"Sidecar") is followed for colours and look only, not for features; the app stays **Aside**.
- **What replaced what:** the old `src/layers`, `src/state`, `src/ui`, `src/window`, `src/platform`, `src/styles` and the old `scripts/verify-*.mts` are gone. New folders: `bridge` (all talk to Rust, in one typed file), `core` (pure, tested helpers), `kit` (building blocks), `theme`, `live`, `home`. Tests are now `npm test` (Node's built-in runner, no extra library); the old verify scripts tested code that no longer exists.

Because End session lives in a footer that never scrolls and the window can be small, the bug cannot recur by resizing.
- **State handling:** one tiny store per window plus a pure "live state machine" (`live/machine.ts`) that turns backend events and button presses into state. It is the part with the most rules, so it has its own tests (20). Events are subscribed to once, in the controller, not inside individual screens.
- **Question detection** is a light heuristic in the frontend (`core/questions.ts`) that only decides whether to show the "Question detected" card; it never triggers an answer. - **Deleting is deferred with Undo.** Deleting a copilot, file or call hides it immediately and shows "Undo" for 8 seconds; the real delete runs when that passes. If the app closes first, nothing was deleted (the safe way round). Chosen over a confirm dialog because it is faster and forgiving.
- **The call-ended recap is shown in the main window**, not in the live window: `end_live_session` closes the live window and brings the main one back in one step, so a recap inside the live window would flash and vanish. The main window listens for the end event and shows a "Call ended" sheet with a link to History.
- **Pre-call checklist tells the truth.** Speech engine, AI key and model, resume, and screen-share hiding are really checked. macOS microphone/system-audio permission cannot be checked ahead of time, so it is shown as information, never a green tick. Failed audio start does not block the call: a dialog offers System Settings or "Start anyway" and the live window keeps the recovery card.
- **Language moved** from the live window's menu to Settings → Speech (it only affects Speechmatics and is not something to change mid-call). It still uses the same saved overlay preferences.
- **Reference check (standing rule):** compared against `references/Repo1-Natively` (`Repo2-OpenCluely` is still missing from this checkout). ## Live window and start-session page rewritten again (2026-09-25, later)

## Redesign Phase 4 decisions (2026-09-26)

- **Autosave counts only real edits.** The page reloads a copilot's attached files after every save. Without a check, that reload would trigger another save every 600 ms, forever. `useAutosave` now ignores values that arrive while it is off, the moment it turns on, and any value identical to the previous one.
- **A new copilot keeps its identity on screen.** Its first save changes the address from `new` to its id. The page keeps the same component key, so it doesn't blink or lose typing focus.
- **Blank company name:** a new copilot waits quietly until it has one. An existing copilot says "Add a company name first" and doesn't save.
- **Files added under Library → All:** the file name decides the type ("resume", "cv" or "curriculum" means a resume; anything else is a document). The Resumes and Documents filters decide for themselves.
- **Silent system audio before a call is "info", not a warning.** Nothing is usually playing yet. A failed start is a real problem and shows "Allow system audio recording".
- **Start waits for any running audio test to let go of the device.** Otherwise the test's "stop" could switch off the call's audio.
- **Key storage wording corrected before it shipped.** Keys are kept in Aside's own settings on this Mac, not the macOS keychain (per `storage/settings.rs`). The Settings hint says "Kept on this Mac".
- **Reference check:** the reference app's history is a search plus rows with a status badge, and it has no file library. The plan already goes further, so nothing was adopted.
